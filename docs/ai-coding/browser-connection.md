# Codex 浏览器连接与恢复

本规范用于采用 Seed 的项目通过已注册工具操作浏览器。先读取当前工具文档，按本次用户要求选择浏览器和入口；工具能力、确认要求与安全限制始终适用。没有浏览器工具时仍可按项目文件开发，浏览器验收明确记为未验证。

## 入口与初始化

- 用户明确指定入口或浏览器时优先遵循；没有指定时，优先使用当前已注册、可正常工作的官方入口。独立代理入口用于已确认的运行时网络需要或对照诊断，不作为所有项目的默认安装项。
- 工具未加载、已加载但调用失败、浏览器发现为空、目标页面失败分别记录。先核对本会话的工具清单，不因自定义入口缺失或失败修改业务代码。
- 首次调用、重置后的初始化与浏览器选择严格按当前工具文档执行。已绑定且有效的浏览器继续复用；实际断连后重新发现，浏览器 ID、标签句柄和变量不可跨内核或跨入口照搬。
- 在不读取无关页面的前提下，可比较官方与自定义入口的发现结果和同一无敏感测试页。一个入口失败不能外推另一个入口或整个浏览器不可用；官方入口发现成功也不能外推页面操作成功。

## 按层定位

| 观察 | 下一步 | 不能据此认定 |
| --- | --- | --- |
| 工具未注册、入口未加载或 Transport closed | 核对工具加载与MCP连接状态，按客户端支持的入口重连 | 项目代码故障或Chrome未安装 |
| inventory返回部分清单及errors | 分别检查浏览器与原生应用错误；只使用确实可用的能力 | 部分成功等于整体恢复 |
| 浏览器为空，扩展明确断开 | 使用官方扩展/客户端连接流程，按工具要求由用户重连 | 扩展已安装就已建立连接 |
| Sky native pipe startup failed等原生管道错误 | 核对官方服务定义、MCP启动上下文、实际重载情况及当前客户端能力 | 一律是网络代理或网页错误 |
| 浏览器可发现，单页报debugger unattached、标签失效或页面辅助能力不可用 | 保留仍有效的浏览器绑定，按工具文档另建无敏感测试页并真实操作；新页也失败后再定位连接层 | 单个旧标签失败等于整个入口断连，或浏览器清单可见就能控制页面 |
| request-header policy或fetch初始化失败 | 核对实际执行策略请求的运行时网络与代理，而非只测终端 | 所有同名错误都属于同一根因 |
| 无敏感测试页完整操作通过，业务页面失败 | 查目标站点、页面权限、业务服务和操作本身 | 应继续重装浏览器工具 |

先使用当前工具支持的恢复步骤；超时可先重置旧JS内核，再按首次调用规则初始化和实测。单页错误不要一直重绑同一失败标签，也不要因此反复选择浏览器或重启整个入口。侧栏加载失败与浏览器控制可能独立，应分别实测。若错误改变，按新证据调整层次。重试应有新依据，不循环重装、改超时或叠加补丁。

## JS重置与MCP重连

`js_reset`清除当前JS内核、变量与控制句柄，不能代替MCP服务重载。修改启动器、服务环境或配置后，需要客户端支持的MCP重连/重载，再进行首次初始化；只重启Chrome也不能证明新的服务配置已生效。

当前客户端支持官方配置重载接口时，可在授权范围内使用并核验本会话工具重新载入；“接口接受刷新”仍不代表真实页面恢复。不通过结束broker猜测自动重连，不自动重启整个客户端或中断其它任务。工具不支持重载、禁止操作客户端自身，或重启会中断任务时，先完成可独立进行的工作，说明具体原因和续作点，由用户在合适时机正常重连。新服务启动证据与页面控制验收分别记录。

## 自定义入口的完整上下文

仅在任务授权范围内检查本机启动器及官方服务定义。保留官方完整command、args、cwd、原sandbox/权限前缀、可信服务登记和必要环境；不能通过增删权限或伪造管道解决发现失败。

STDIO MCP的`env`显式赋值与`env_vars`转发白名单用途不同。复制官方静态env表不等于已转发父进程的连接上下文；转发名单也不意味着每个字段无条件必填。对照当前版本官方清单核对名称，只有实际启动合同或官方校验明确要求时，才判断缺失是否阻塞。不能仅凭名单新增缺失即退出的守卫、移除官方校验或从其它进程借值。配置、字段存在性、官方服务启动与真实连接分别验证。

诊断只输出必要字段名、存在/缺失布尔值、版本和脱敏启动回执。不打印完整环境，不复制连接标识、IPC地址或验证身份值，不从其它进程借用连接。不得读取浏览器凭据、历史或profile来修复工具；系统或扩展权限由支持的官方流程处理。

客户端自动生成的同名node_repl/cua_repl配置不作为手工修复持久入口。独立入口只增量修改自己拥有的配置，保留原转发项及无关字段；先做最小备份或可逆差异，解析后核对有效配置，再重连。不能修改官方插件缓存、签名应用资源、可信登记、TLS校验或安全策略来制造成功。历史本机兼容补丁不随Seed安装；未知版本停止适配，不强制复用旧哈希或旧超时。

代理仅在证据表明确有需要时配置到实际执行请求的服务/工作进程，保护必要的本地直连例外。代理地址、端口、启动路径与兼容脚本留在设备授权状态区或项目.local。终端联网、无凭据HTTP响应或启动器check成功，都不能证明浏览器控制可用。

## 真实验收与资源收尾

通过同一已注册浏览器入口依次完成：新初始化与发现 → 打开无敏感测试页 → 读取可见内容 → 点击并观察变化/跳转 → 刷新并再次读取 → 截图。声称重置后仍可用时，另做一次新内核初始化和页面操作；声称客户端/整机重启恢复时，必须有对应重启后的独立复验。

记录入口、客户端/工具版本、发生时间、各步骤结果、失败层和未验证范围。不得用缓存的页面、测试脚本通过或先前设备的成功代替本次真实操作；不把单次成功称为持续稳定或所有项目已恢复。

按[任务生命周期](task-lifecycle.md)关闭本任务临时标签、恢复本任务临时调试设置；用户原有页面保留并按工具能力交还控制。超时可能已创建页面，先通过工具核对归属和实际副作用再重试，避免重复开页；无法验证清理就明确记为unknown/pending，不使用Shell绕过浏览器工具。

## 来源、分发与证据边界

本规范由主仓浏览器连接修复任务回流。前阶段发现自定义入口与官方转发名单不同；补齐名称后字段仍为空。曾据此添加缺失即退出的守卫，导致代理工具无法加载。这一因果推断已撤回：获授权只读核对当前官方初始化代码后，确认名单不是无条件必填合同；移除自行添加的退出守卫，保留官方校验与脱敏诊断。独立STDIO握手和工具清单检查通过，经官方配置重载后，本会话代理工具重新载入。

同轮实际注册代理入口完成浏览器发现、全新本地页开页与读取、同步弹窗点击、全选9项、刷新和截图；两次JS重置后分别重新绑定并点击通过。公开测试页的点击跳转和刷新也通过，临时标签关闭并回读确认，原业务成果页保留。实际新启动仍无上述转发字段，不能再将它们缺失列为本轮发现失败根因。此前原生管道错误的具体根因尚未建立，当前未再复现；不因此宣称修复了官方原生管道实现。

官方入口同轮在新本地标签也完成开页、读取、点击、全选、刷新、截图及JS重置后复验。旧标签失败不能外推整个入口失效，扩展侧栏错误与页面控制分别验证。当前两个入口均在本轮验证范围可用；客户端冷启动、整机重启、长期稳定和其它设备仍需独立验收。前阶段失败证据保留，后续结果追加收录。

当前公开配置依据为[官方MCP文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)（2026-10-22核对）；界面/API以当前实际工具文档为准。来源任务最小摘要留在Seed来源记录，不复制设备参数或完整聊天到派生项目。

Seed Git与Kit携带同一规范和Agent读取入口；已有项目通过自己的模板升级增量采用，保护现有用户入口偏好和本机配置。不批量改写所有项目、不安装代理、不自动发布或宣称已采用。采用方法见[迁移说明](../template-migrations/20261022-codex-browser-connection.md)。
