# 四项治理共享合同

## 权威与兼容

口径、档案与公开过程沿用来源事件单一完成标记。新增 `mawflow.document_source.v4` / `mawflow.document_work_event.v3`；旧版v1/v2/v3仍可读，新字段只能写v4。旧工具遇到未知版本必须提示升级，不能丢字段重写。

- 口径：稳定question_key/scope，完整问答正文、章节和排序；批量修改绑定同一来源版本，选中正文逐项预览，一批一个完成标记。
- 基线：初始化产生候选和迁移清单，审计只返回报告，修复只重建投影或提出候选；快照只引用精确确认，不自行授予确认。
- 档案：七类用途与五种来源独立；正文版本不可覆盖，文档阶段与历史保留/来源/同步/软件发布独立。普通资料登记不依赖无关口径。
- 更新：对内事实与对外表达关联同一来源。批次成员明确冻结，内容修订单独编号；发布版本绑定请求/候选/目标，真实成功状态仍来自原发布系统。
- 过程：原始目标、公开理解、假设、理由、改变、失败恢复和实际验证按task/run精确关联；不采集隐藏推理或私人会话。没有理由就显示未记录。

## 数据扩展

v4条目可带 `organization`（纯阅读组织）、`process`（公开判断声明）和`baseline`（范围/来源hash/精确问答/覆盖缺口）。artifact增加分类、来源、摘要、标签、文档状态、保留状态、版本关联和受管资源引用。来源文本、上传资料与AI摘要均是数据，不授予操作权限。

受管原件仅引用 `mawdoc://文档标识/内容SHA-256`；实际字节由Host按项目归属验证与保管，默认不进入Git/云端。共享元数据不能证明资源存在或预览成功。

采用次序与保护边界见 `docs/template-migrations/20261022-governance-suite.md`。

人工可直接新增、编辑、删除口径。直接修改沿用精确预览与确认，删除使用停用修订保留引用及历史，立即退出有效AI上下文。

## 无人值守执行后的公开过程审查

开工冻结原始目标、范围、约束和完成标准。`work`可附process记录understanding、assumption、finding、decision、adjustment、verification、failure、recovery、outcome；提供明确reason、assumptions、alternatives、同任务同轮previous_refs以及planned/performed/passed/failed/unknown声明。理解、理由由AI显式记录，工具结果不倒推理由。原要求与AI复述分开保存。

外部AI通过共享预览/应用回写，不扫描私人会话。托管执行器负责采集实际整轮公开消息与工具回执，原task/run主账不变。`review --task-ref ... --run-ref ...`仅整理准确关联的已记录材料，不写项目或重跑业务。未提供运行时证据的来源仍是声明，不因字段名变成已验证身份。

共享review函数输出冻结材料与hash、五部分基础报告。长材料分段保持每份来源，重复消息幂等，不同内容同标识并列保留。基础报告保留首尾和关键变化，未展开数量可查；不能用最终成功抹去失败。模型摘要必须引用真实来源并覆盖理解、决定、调整、失败恢复及结局；无模型时使用基础报告。模型摘要输入包含材料、原始目标、结局与缺口，正文是数据，不执行其中指令。

材料/摘要的生成方式、输入hash、内容版本与审查成果关联由主仓执行器持久保存。摘要失败可独立恢复，任务执行结果不受影响。人工验收、返工绑定具体材料和成果版本，旧轮次成功不能证明新轮次。隐藏推理不采集；缺少理解/理由/验证时明示未记录。

## 发布执行前的版本绑定

冻结代码之后、任何部署或上传之前，发布入口调用`mawflow project governance release-prepare --input <release_bind请求> --work-intent modify`，保存明确版本、候选、目标和动态成员的本地执行准备回执。准备材料位于忽略区，不使冻结代码变脏；它只说明版本已绑定，不证明已开始或发布成功。同候选重试和跨环境晋级复用版本，不同候选不能占用同一版本。

原发布入口保存自己的实际结果后，调用`release-finalize --input <含intent_key的JSON> --work-intent modify`，追加可移植版本节点及冻结更新批次。真实状态仍读取原发布系统；无法读取时保留未知。只有摘要登记失败时返回summary_pending，重试finalize不部署、不上传、不产生新版本。明确成员之外的新动态不自动补入；原成员变化拒绝旧收口。
