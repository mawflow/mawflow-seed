# 任务生命周期与资源收尾

本规范适用于只读分析、开发、测试、部署和交付。六阶段规范决定适用要求，本规范约束一次任务如何执行与结束。Task、WorkItem、Evidence、Approval、Release 仍由原领域持有；阶段名称不是新增数据库状态。没有平台任务时引用当前可定位的用户指令，不强制创建工单或安装工具。

## 对象与授权

- 任务保持稳定 `task_ref`；目标、范围或完成标准变化时记录范围修订，核对新增授权，保留旧版本。
- 每次重试、返工或接力有独立 `run_ref`，沿用任务引用；旧尝试与迟到回执不得覆盖新结果或重开已关闭的同版本任务。
- 资源属于具体执行尝试；区分创建、借用和共享，记录用途、寿命和回收方式。物理标识、进程启动时间、工具会话与设备绑定只留在本机授权状态区，不进入共享规则。
- 已有授权在原对象、环境和动作范围内延续，不为每个阶段重复确认。只读任务写路径为空，不因记录、收口或资源治理写项目文件。发布、业务数据清理和共享服务控制仍遵循各自授权。

## 正常阶段

| 阶段 | 行为与退出条件 |
| --- | --- |
| 定界 scoped | 明确目标、类型、读写/禁止范围、环境、完成标准和已有授权；只询问实际缺失信息。 |
| 准备 preparing | 读取项目与模块规则，冻结源码/环境基线，检查工作区、依赖、真实验证入口和资源；满足当前工作需要才执行。 |
| 执行 executing | 在范围内增量工作，按需复用资源；记录关键决定、变化及可恢复里程碑，不收录完整聊天。 |
| 验证 verifying | 按影响运行真实检查；证据绑定候选版本、环境和范围，变化仅重验受影响部分。失败可在原授权内修正，未运行明确列出。 |
| 收尾 closing | 保存成果与证据，按项目及执行器职责完成适用的提交/推送、文档来源与动态；回收资源并核对保留项。只读不执行Git交付。 |
| 执行结束 ended | 分别报告结果、验证、交付、部署、真人验收和资源状态，给出未完成项及下一步；不遗留无人负责的活动。 |

小任务可在一次工作中完成各项判断，不要求逐阶段落文档；迭代增加依赖、里程碑和恢复点；正式交付增加冻结候选、审批、回滚及目标回读。真实平台状态通过现有服务映射，不由文件快照推进。

## 等待、异常与恢复

| 情况 | 要求 |
| --- | --- |
| blocked | 写明原因、影响、解除条件，继续独立工作；释放等待期间不需要的资源。 |
| waiting_human | 明确所需输入/动作及续作位置，只保留必要交接现场，不无限持有测试进程或重任务名额。 |
| paused | 仅依用户明确暂停要求进入，停止新增动作并保存恢复点；不把普通阻塞称为用户暂停。 |
| cancelled | 停止本任务生产者，保存已发生变化与证据，回收资源；不默认为取消回滚已提交、已发布或已生效业务变化。 |
| failed / interrupted | 保留失败与未知，不凭进程退出认定完成；有限重试，先核对提交、数据库写入及发布实际结果，避免重复副作用。 |
| handoff / resume | 交接任务、范围版本、基线、成果、证据、未完成项、资源与下一步；恢复先重核授权/源码/环境/归属，防止双写，从未完成步骤继续。 |

正常退出、取消、超时与交接均执行收尾。崩溃时受管执行器尽力清理，恢复后按既有资源凭据对账；只靠规范文字不能保证崩溃回收。租约到期先核对存活与归属，不按时间批量杀进程。旧执行者仍能写入时不得提前交给新执行者；使用现有租约/版本保护。

## 资源生命周期

申请或借用 → 使用/复用 → 用途结束 → 释放或有条件保留 → 回读结果。先保存必要成果与证据，再按依赖逆序停止本任务活动，最后释放连接和名额。不能在子任务仍运行时释放保护它的锁。

| 资源 | 默认处理及保护条件 |
| --- | --- |
| 用户原有浏览器标签 | 交还AI控制，页面保留；不因接管变成本任务可关闭资源。 |
| AI临时新标签 | 用完关闭，或依工具的回合自动收尾；搜索、中间、重复、错误、空白页不标记长期保留。 |
| 成果/交接页面 | 仅真实成果或必要等待现场保留；未保存编辑、上传或下载未完成时先保护工作，不擅自保存/丢弃。保留页面与交还控制分别验证。 |
| 进程、watcher、日志跟随 | 停止本任务专用且无用途实例及子进程；停止前校验创建凭据、进程启动时间与执行归属，不能仅凭PID、端口或进程名。 |
| 服务、容器、隧道、连接 | 回收本任务专用临时实例，正常结束本任务事务；共享、借用或验收服务按原约定保留，不全局杀连接、不隐式提交事务。 |
| 锁、执行名额 | 由原持有者通过原机制释放；沿用开发资源包装器语义，不删除锁文件冒充释放。 |
| 工作树、分支、文件、测试数据 | 按原交付/验收策略处理；未提交变化、待评审成果与恢复证据保留。业务数据、缓存、凭据、浏览器profile和共享卷不属于默认清理。 |
| 临时调试设置 | 恢复本任务施加的视口、拦截等设置，不覆盖用户原有设置。 |

保留项至少有用途、责任归属和复查条件；复查到期不自动删除。历史资源无法确认归属时只报告，不批量关闭、停止或删除。资源记录不是任意命令执行清单。

### 浏览器适配

先读取本会话实际工具文档。支持显式释放则按文档执行；只支持回合自动收尾时依赖该机制，不虚构 `release()`，不以 `js_reset`、清空变量或结束broker证明释放，不用Shell绕过浏览器工具。

当前提供 `markDeliverable()` / `markHandoff()` 的适配器，仅对成果/必要交接调用；不得标记普通调试页。标记可能仅本回合有效，续作须按工具文档重新判断。用户标签未保留标记通常在回合结束交还控制，新建临时标签通常自动关闭，但必须以当前工具文档和实际回执为准，不能外推其它工具。

依赖回合结束自动清理且尚无回执时写 `pending_automatic`，后续回执或独立复验后才能记录已释放。保留标签不能证明控制已交还；工具不能分别表达二者时明确能力限制。无需浏览器时不为验收而接管用户现有页面。

## 完成条件与回执

本次执行结果为 pending/succeeded/partial/failed/cancelled/interrupted；业务关闭独立为 open/ready_for_review/closed/cancelled。只有范围内完成条件全部满足才可声明成功；需要真人验收的任务由有权真人决定，范围包含发布时实际目标回读也是完成条件。AI自测、Git推送、文档存在与资源回收分别不能外推其它维度。

资源状态独立为 active/released/retained/pending_automatic/failed/unknown；未使用资源用空清单，不虚构回收。仍有待自动回收、失败或未知时总体资源状态不能写 passed。保留项符合用途且控制状态明确可以正常收尾；失败项必须说明责任与下一步，功能成功不掩盖收尾缺口。

最终简化收口增加一行“资源收尾：已回收……；保留……（用途）；未验证/失败……；下一步……”。机器字段为 `task_lifecycle_status`、`resource_cleanup_status`；需要详细证据时引用原有任务快照、检查回执与运行器结果。

## 文件侧检查与兼容

在既有 `mawflow.standard_task_snapshot.v1` 中使用可选 `lifecycle` 扩展，结构见 `docs/standards/examples/task-lifecycle.yaml` 和 `.maw/schemas/task-lifecycle.schema.json`。执行：

```bash
python3 ops/scripts/manage-project-standards.py validate-task --input docs/standards/examples/task-lifecycle.yaml
```

资源回执绑定task_ref、scope_revision、run_ref、resource_key、action、源码版本、环境、scope_hash、记录引用、带时区观察时间及脱敏文件哈希。

检查只读，只核验声明、范围、证据文件哈希与同一执行尝试引用，不操作浏览器、进程、数据库或远端，不证明授权真实性、实际回收或真人行为。原快照没有扩展时返回 lifecycle_status=not_adopted，不阻断既有工作，也不冒充已接入。共享回执只引用脱敏证据；本机私有原始记录不自动读取。

Seed和Kit必须携带同一契约、检查实现、例子和升级资产；已有项目增量采用，保护项目事实与历史。默认新任务生效，运行中任务在安全恢复点补齐；不改写历史、不批量清理旧标签。Host/Runner可按能力接入原有受管执行器，本规范不安装常驻清理器或扩大停服务权限；已安装Host、浏览器运行验收、公共发行与项目采用分别记录。

## 执行协议修订 2

新任务声明 `protocol_revision: 2`。失败、部分完成、取消和中断需 `outcome_reason_ref`；继续执行使用新 run_ref，并通过 continuation.previous_run_ref/checkpoint_ref/ownership_check_ref 引用上一轮、恢复点和资源归属核对。未知资源不得接管；实际工具重连后重新获取句柄，不复用旧控制变量。旧修订保留原声明，不伪造恢复记录。

浏览器资源的页面状态与控制租约分别记录：resource.state/action/retention 表示关闭或保留页面，control.state/action/release_mode/receipt 表示交还控制。保留页面的 retain 回执不能证明 release_control；可保留用户查看页面并另附真实控制释放回执。支持显式释放时使用 explicit；只支持自动回收时先记 automatic/pending_automatic，取得真实回执才记 released；不支持时为 unsupported，不能报告已释放。旧 close 回执仍可证明本任务创建标签已关闭。

临时调试设置可以借用共享载体，但恢复只限本任务已授权变更：temporary_change 记录 owner_run_ref、before_hash、applied_hash、authorization_ref，restore 回执的 restored_hash 必须等于 before_hash。不得以恢复名义停止他人服务或回写无法证明归属的状态。资源动作按种类校验，服务/进程 stop、连接/锁/临时文件/工作树 release、调试设置 restore，浏览器 close/release_control；资源删除与共享状态变更仍遵守原授权。
