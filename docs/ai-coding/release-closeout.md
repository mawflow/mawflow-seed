# 发布全部的会话收口

本规范补充 TINST-020 和 TINST-014。先判断本轮改动是否影响组件运行；仅治理文档变动写“本轮无需业务发布”，不附发布确认。已有发布授权在明确范围内延续，不重复索取确认。

## 收口展示

有发布影响时，先说明环境、部署目标、来源仓库和候选提交，再按组件列出：

| 组件 | 上次成功发布提交 | 本次候选提交 | 状态与原因 |
| --- | --- | --- | --- |
| api | 12ab34cd | 56ef7890 | 待发布：组件源码有变化 |
| web | 90ab12cd | 56ef7890 | 无变化跳过：仅其它路径变化 |

表格是格式示例，实际输出必须来自当前项目事实和新鲜规划结果。提交可展示短 SHA，证据和状态文件保留完整 SHA；外部 Git 组件使用自身仓库提交。测试 dirty 快照须明确标记，不能只用 SHA 判断相同。

- 待发布：首次发布、组件或共享发布路径、覆盖层、部署范围等变化；没有成功记录显示“无（首次发布）”。
- 已发布：本轮实际执行发布且目标验证成功，给出发布记录；历史成功记录只放在“上次成功发布提交”，不能冒充本轮已发布。
- 无变化跳过：成功基线可核验，且规划确认无变化；保留原实际成功提交。
- 失败：本轮执行失败，说明原因和重试入口；失败组件不推进成功基线。
- 阻塞/未验证：状态损坏、提交或目标不可确认、未执行规划等，明确缺口，不能写成无变化跳过。

简化收口可合并同状态组件，但不能省略失败、未知、目标差异或待发布范围。机器字段保持 `release_update_status`、`release_commands` 和 `release_confirmation_prompt`，无发布影响时后两项为 `not_required`。

## 统一入口与采用情况

已采用发布全部能力的项目，`release_commands` 首先给出 `#发布全部 到 <environment>`，同时明确部署目标；默认环境必须从聚合配置读取。再提供配置中已有的单组件指令供选择部分发布。多个部署目标需要显式选择，CLI 示例：

```bash
python3 ops/scripts/plan-release-components.py '#发布全部 到 staging' --deployment-target staging-app --format json
```

该 CLI 只生成计划。`#发布全部` 按选定目标显式 `component_refs` 与上次成功提交筛选，可能包含此前会话遗留的待发布组件；收口必须显示这一范围，不能把它等同于本轮修改组件。不能跨环境、自动合并多个服务器或纳入未登记组件。

先核对项目实际指令与脚本能力。尚未采用的项目保留已登记单组件入口，说明需模板升级；不能宣称已支持 `--all`、改写采用版本或为展示收口复制整套发布器。Seed 源码完成、Kit 公共发行、项目采用、应用发布和真人验收分别说明。

## 确认与执行

需要新发布授权时，先形成可核验的具体计划，并使用绑定范围的文案：

> 待发布：api；环境：staging；部署目标：staging-app；候选提交：56ef7890。回复“确认发布全部”将发布上述待发布范围；也可复制单组件指令选择部分发布。

“确认发布全部 / 确认 / 是 / 全部发布”只确认最近一次明确列出的环境、部署目标、组件、候选源码及 SQL/迁移范围，不扩大为全项目发布。用户另行发出 `#发布全部` 时，按其明确选择的目标重新规划全部候选，并遵循项目发布授权。确认前后源码、目标、组件或迁移范围变化时，重新核对授权覆盖，不静默扩大发布范围。

部分成功时分别报告成功、失败、跳过和阻塞；只将实际发布且验证成功的组件写入 `artifacts/release-state/<environment>/<deployment_target_key>/<app_key>.json` 或项目等价状态。旧环境/组件路径只读兼容。构建成功、Git push、规划成功、生成手册或写入声明不能替代远端发布验证；生产审计、来源分支与 clean/latest 门继续按项目发布规则执行。

## 自动版本选择

项目已声明自动版本策略时，版本号由执行器按 SemVer 确定，无需单独请求人工授权。先核对全部发布目标的已发布稳定版本和tag：复用高于已发布版本的未公开候选，否则默认将最高稳定版patch加一；明确的兼容能力或破坏性变更自动选择minor/major。无源码变化且目标一致时跳过，不为跳过升版；已公开或用于验收的正式tag不可移动，冲突选择新版本。用户显式版本优先；版本选择不能替代本次发布授权、审计和远端回读。Seed维护发行默认采用此自动策略，Git与Kit版本及Contract major继续对齐。
