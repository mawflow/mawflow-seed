# Seed 与本地产品工作台

本地产品工作台的核心用途之一是 Seed 规范可视化和 Seed 项目管理。Seed 是规范、声明、操作契约与可迁移资产的权威来源；Kit 提供同源编译、诊断与预览算法；工作台把这些能力转成可理解、可维护、可追踪的项目操作。三者维护同一项目，不因入口不同复制配置或项目。

## 共同闭环

| Seed 能力 | 工作台用途 | 必须回读的证据 |
| --- | --- | --- |
| 项目、组件、模块、环境声明 | 展示项目地图、字段来源和范围；在现有 ChangeSet 中维护 | 同源 Catalog、声明与投影指纹，目标项目扩展保留 |
| Seed 锁、工具兼容、模板来源 | 显示采用版本、支持版本、漂移和迁移预览 | 不可变版本/提交、来源校验、预览差异及采用后复检 |
| 规范与诊断 | 展示适用/未采用/未检查/失败/过期及原因，关联修复任务 | 规则来源、检查范围、时间与失效原因，不把任务完成当规则通过 |
| 配置诊断与修复 | 从环境配置或项目诊断定位声明、绑定和消费者断点 | [TINST-045](../ai-instructions/instructions/configuration-repair.md)的分层回执与修复后指纹 |
| 需求、任务、进度、手册、证据 | 管理 Seed 项目的研发与运维闭环 | 各自权威任务和证据，不让规范检查替代业务验收 |
| 可选运行健康 | 使用原生或独立采集安全投影辅助运维 | 接入状态、目标身份、采样时间和有效性；未采用不扣规范分 |

## 接入与兼容

工作台通过受支持的 Kit Catalog/Project OS 和受控项目文件消费规范，不在 UI 硬编码第二份 Seed 默认值。CLI、Agent 与工作台的相同操作应得到同源结论；工作台保存字段时写回项目允许的权威入口，本机绑定只存引用，云端投影不成为本机秘密或源码的副本。

新 Seed 能力的交付须分别记录：规范与 Git/Kit 资产、项目采用、工作台适配、实际 Host 安装/进程版本、自动验证和真人验收。支持版本不足时显示升级或待适配，不把“已发布 Seed”显示成“工作台已支持”。旧项目未采用、可选组件未启用、CLI/工作台不可用均保持显式兼容状态，不阻断无关开发。

新增可视化需求先检查现有项目地图、环境、项目诊断和任务入口，再增量适配；不创建第二套配置中心、诊断主账或必装运行健康服务。工作台不能因项目自定义 schema 扩大本机权限，自动读取页面保持有界只读；写入复用预览、指纹、确认、回滚与证据规则。

当前文档定义通用消费契约，不宣称某个工作台版本已实现所有映射。此增量在 v2.14.0 冻结之后开发，公共发行与目标工作台采用分别验收；Seed 项目仍可直接通过项目文件、Agent 和 CLI 工作。
