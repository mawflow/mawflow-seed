# 交付与移交清单

## 进入条件

交付对象、接收方、范围和分享/客户写入授权明确；项目内准备文档不自动触发外部分享或推送。

## 规范分组

- 客户代码候选：固定内部来源和最新目标基线；在真实目标公共API/依赖下验证范围与实际制品，内部编译通过不能代替。保全范围外源码与POM，不用临时验证适配污染客户源码。
- 数据库：代码仓交付与SQL交接独立；只读诊断、审核执行件、实际执行、应用复诊分别记录。不给接收方待直接重放的源迁移，不能从旧环境回执外推本批对齐。
- 文档：按接收者提供用户/技术/运维/UAT说明、已知限制、责任及恢复入口；内部诊断、账号和原始日志按权限独立交付。
- 审计：范围、来源、候选/制品哈希、测试、发布及决定回链原有对象，不建立可变结果第二账本。
- 更新快照：按本批冻结来源到上次已交付来源的增量编写，面向使用者描述变化；只刷新基线或无业务增量时明确说明，不虚构正式版本。累计说明与不可变批次快照关联同一变化。
- 移交：交付、目标合入、部署、数据对齐、签名激活、真实角色验证和真人验收分别记账，明确遗留责任与下一步。

## 完成条件

接收者能使用、维护并追溯本次范围；所需引用可访问且有完整哈希/冻结关系。单模块UAT沿用既有交付标准，文档审阅不等于真人业务验收。并发目标基线更新只使受影响候选失效；保留历史回执，不改写正式tag和已确认版本。
