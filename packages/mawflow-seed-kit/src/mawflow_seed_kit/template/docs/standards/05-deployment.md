# 部署与发布清单

## 进入条件

用户已授权明确组件、目标、动作及数据范围；候选验证和项目发布门满足。计划、预览、审批和执行遵守项目实际流程，已有范围内授权延续。正式源、干净提交及tag按项目生命周期核验。

## 规范分组

1. 冻结：来源提交、目标实际基线、组件范围、制品清单/哈希、版本、配置和依赖。
2. 方案：复用现有环境、必要构建、迁移顺序、备份恢复、停机影响和回滚。只构建/上传变化且可信输入，不默认重启无关服务。
3. 数据库：只读核验目标实例、database/schema、方言/模式、租户和实际程序版本；代码更新计划不证明已部署。源码SQL不直接等于本环境执行件。
4. 数据保护：先目标诊断，再按允许集合生成审核增量、旧值/并发/影响上限/超时断言、可恢复备份、事务及恢复。不得重放已消费修复、全局清缓存或破坏目标业务数据。DBA辅助执行不替代应用自身DataSource复诊。
5. 执行与回读：写明成功/部分成功/失败、实际目标版本、配置/结构/权限/健康及回滚信息，分别保留回执。
6. 更新说明：从已验证变化及真实部署回执生成环境/版本说明；失败亦有记录，不把Git推送或文档生成称为上线。

## 完成条件与恢复

目标版本和本范围运行证据可核验。数据库、程序、外部集成、Host及公开包按各自通道记账，任何一个成功不推导其它成功。续跑先核对原来源、目标基线、摘要和已完成步骤；输入未变复用有效部分，变化时只重验受影响部分。已提交后恢复须重新诊断和单独授权，不把ROLLBACK描述为提交后恢复。
