# 测试与质量清单

## 进入条件与授权

先确定模块/页面/流程、源码版本、目标环境、角色、数据与动作范围，复用已有有效授权。测试身份使用许可不能推导为数据库直改、生产部署或客户同步。网络路径由项目声明：连接可达、应用登录、数据库身份、实际部署版本均分别核验。

## 选择范围

| 情况 | 默认深度 |
| --- | --- |
| 普通文档规范 | 内容、引用与相关一致性检查 |
| 单模块小修复 | 定向测试、相关静态检查；页面行为变化补实际页面验证 |
| 状态、权限、接口兼容 | 正常与拒绝、真实角色、依赖契约和并发 |
| 公共类型、构建依赖、发布 | 受影响组件构建、集成和实际候选制品 |
| 数据迁移 | 目标诊断、保全、异常拒绝、重复执行及恢复路径 |
| 正式交付 | 实际目标依赖/环境、候选与独立验收条件 |

不把全量检查设为所有任务默认；发布和跨模块风险需要的检查仍保留。测试计划记录选中、跳过及原因，风险或范围变化时增量调整。

## 方法与证据

使用真实角色验证正常操作和越权拒绝；权限模拟、万能管理员、静态断言及合成数据各自标明。页面验证记录有数据交互、错误/空态、刷新回读、关键动作和项目配置的视口；空态不外推有数据交互通过。相同业务写入无需在每个尺寸重复。

Test Contract注册命令、suite及journey，未接入或空套件明确 not_run/pending，不是passed。测试证据包括源码/制品、目标环境、范围、方法、结果与引用。HTTP200、会话ready、签名回调成功和实际内容显示是不同证据。开发成功不能替代SIT/UAT或真人验收；缺账号、数据、工具和外部服务时标未验证及下一步。

## 完成条件

本任务选中测试、缺陷复测、覆盖与未覆盖明确，证据仍匹配版本/环境/范围。单项通过只覆盖该专项；整体状态与真人验收独立。
