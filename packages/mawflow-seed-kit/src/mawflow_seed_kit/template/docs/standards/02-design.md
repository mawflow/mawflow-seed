# 需求与设计清单

## 进入条件

任务有待确认需求或影响模块、业务状态、接口、数据、权限及外部依赖；单纯内部小修复仅核对相关已有契约。

## 规范分组

- 需求基线：业务流程、角色、异常、验收目标和当前确认范围。
- 模块地图：明确页面/API/表/状态与路径所有权；技术组件不等于业务模块。
- 技术地图：先查已有能力、API、基类、资源和经验；新增公共能力注明消费者和适用条件。
- 数据、接口与权限：身份、租户/组织、状态并发、兼容、失败及审计；拒绝场景与正常场景同时定义。
- 外部依赖：契约、版本、责任方、实际配置、联调和回执；模拟响应不能代替真实接入。
- 评审：结论区分已确认、建议与待确认，记录来源和影响。

## 最小产物与完成条件

本任务相关需求/设计、模块与能力引用、验收标准及依赖缺口。关键口径有确认依据，未知项可见。根据变更维护受影响档案，不要求每个页面创建完整新文档或把全部设计复制到阶段目录。
