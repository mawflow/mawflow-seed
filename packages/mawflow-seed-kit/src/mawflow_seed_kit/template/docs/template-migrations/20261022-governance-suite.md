# 四项治理增量采用

版本：Seed/Kit 2.17.0开发候选，Contract保持2；正式稳定分发、项目采用、Host安装与真人验收分别记录。

## 依赖与次序

1. 在Seed完成来源v4/工作事件v3、全文口径和人工维护、基线、明确档案、版本批次、公开过程材料与兼容回归。
2. 主仓从已绑定独立Seed固定提交增量采用，保留主仓真实组件、发布、映射、模块和已有较新能力；不得整包覆盖。
3. 主仓接入可信Kit、原件资源、自然语言修订和基线任务、工作台四域、托管采集/自动摘要及发布版本钩子，验证隔离候选。
4. 公共渠道项目仅采用经校验稳定tag和同版Kit；先完成公开候选准入，不以私有工作目录或rc绕过。
5. 真实目标完整冻结主题和历史，给每项迁移去向；展示组织可重建，语义修改作为候选。四域分别回读，再由人工确认业务与验收成果。

## 增量文件与保护

采用 `.maw/project-governance.yaml`、`ops/scripts/maw_governance/`、来源捕获器、治理CLI、更新store/schema、Agent语义、共享规范与本升级资产。旧来源与旧动态、档案身份及固定版本保留；未知版本不允许降级写。

保留README、业务code、真实app_key、发布配置、仓库映射、模块档案、私有规则、秘密和本机overlay；主仓已有资源策略或发布适配若较新应保留，只合入所需语义。

## 兼容及回退

- 新读器兼容旧来源，旧项目继续只读。对真实已有Seed项目，启用新写器前采用声明；失败明确升级需求。
- 人工新增、编辑、删除均按完整正文及精确差异确认，删除保留历史；自然语言候选不覆盖当前权威。
- 普通方案/原件登记不被无关口径阻断；文件保存与登记回执、原件与预览、文档版本与软件版本分别核验。
- 版本绑定不是部署成功；目标结果由原发布系统回读且匹配候选。摘要失败可单独恢复，旧导出和旧轮次保持不变。
- 退回旧Host/Kit时保留所有新来源，不删除新字段伪造兼容。项目可继续阅读固定文档，写操作提示升级。

## 验收

覆盖旧数据、新建Kit物化、源码/Kit字节一致、精确批量与中断、117主题全量盘点、独立入档与登记恢复、原件声明、版本重试/冲突/跨环境、摘要冻结/更正/失败恢复、超过8条公开消息及晚期调整/失败恢复、跨轮拒绝与材料缺口。真实模型、Host/工作台和实际项目由主仓验收。
