# 配置诊断与修复

## 元信息

- ID：TINST-045
- 类型：项目指令
- 状态：启用
- 推荐调用：`#配置修复：<症状、执行入口、环境或目标>`
- 只读调用：`#配置诊断：<范围>`
- 精确调用：`#T045` / `#T045/只读`
- 触发词：#配置修复、#配置诊断、配置已保存但检测不到、界面配置与执行不一致、配置来源漂移
- 适用范围：Seed 项目的配置识别、覆盖优先级、资源绑定、工具兼容、缓存与执行适配问题。

## 目标与工作台关系

恢复“项目声明 → 本机绑定 → 实际消费者 → 验证回执”的一致性。本地产品工作台是 Seed 规范的主要可视化和项目管理消费者：项目、组件、模块、环境、诊断和升级均应消费 Seed 权威事实及同源 Kit，配置表单不建立另一份配置主账。

本指令是可由 Agent 执行的协议，不是 Shell 命令。工作台可将同一诊断结论生成可预览任务；没有工作台或缺少适配器时直接按本协议执行。新增规范不代表已安装工作台自动支持；必须分别记录 Seed 版本、Kit/Host 支持版本及实际工作台验证结果。

## 输入与授权

- 最小输入是症状或失败入口。优先从当前任务取得项目、组件、环境、部署目标和已有授权；只问无法唯一确定且影响操作的信息。
- `#配置诊断` 与 `/只读` 只检查，不写配置、记录、任务或缓存，不重启、不连接未授权目标。已授权的只读连接也须与页面读取分开。
- `#配置修复` 先完成只读定位和具体差异预览，再在已有授权内修复可逆配置或消费者代码；不对已授权的普通修复重复求批。
- 生产发布、外部写入、凭据导出、Host 更新与服务重启继续按项目自身规则和本轮授权处理。本指令不扩大授权，也不将连接测试视为发布授权。
- 用户只说“配置修复”且目标不明确时，先做当前项目的只读诊断；关键词冲突或多个目标无法消歧时先确认目标。

## 执行步骤

1. **确定身份与版本。** 按 Agent 入口读取项目、组件、模块、环境和策略，定位实际工作副本、配置档、执行进程及消费者版本。核对 Seed 锁、模板来源与 Kit/Host 兼容性，区分源代码、已安装工具和正在运行的进程。只读任务不修改版本锁。
2. **追踪配置来源。** 从失败的真实入口沿界面/API、共享声明、本机覆盖、资源/凭据引用、加载器、消费者和运行进程逐层取证。复用项目权威加载器和逻辑 key 的 explain 能力，记录命中来源、优先级、启用状态、文件/投影指纹和时间；仅检查当前范围，不扫描全部私有存储。界面绿色只能证明其已核验的层级。
3. **分类根因。** 区分 `missing_declaration`、`binding_unavailable`、`scope_mismatch`、`source_conflict`、`consumer_adapter_gap`、`tool_version_unsupported`、`stale_runtime`、`permission_denied`、`connection_failed` 与 `unknown`。配置不存在、读取不到、不支持、连接失败分别说明。证据不足保留 unknown，不能要求用户重填已有配置来掩盖适配缺口。
4. **生成修复预览。** 按[回执模板](../templates/configuration-repair-report.md)列出证据、实际断点、允许修改路径、具体差异、验证方法、影响、回退和需要的既有权限。已有工作台/API 配置为权威时修消费者适配；多个来源冲突按项目规则裁决，不能用“最后更新时间”选边。兼容旧配置只在权威来源确实缺席且项目允许时采用；已登记但无效的目标不能静默回退到另一主机或凭据。
5. **执行最小修复。** 优先复用统一加载器、资源解析和官方 Kit；绑定仅存稳定引用，秘密仅由授权执行进程按需解析。写前核对预览指纹，发生变化即重算；保留注释、用户扩展及无关改动，按项目入口备份、原子写与失败回退。消费者缺口通过有范围的代码修复和回归测试处理，不把秘密复制到旧配置文件。需要安装/重启但未授权时保留已完成的可审查结果，明确剩余动作。
6. **逐层回读。** 从原先失败的执行入口重新 plan/doctor，验证实际选用的项目、环境、目标与来源。按授权另做严格身份校验的只读连接；若实际执行也已授权，再按专门流程执行及回读。检查历史资源保留、失败关闭和幂等性，第二次诊断应无待修复差异。界面、CLI、发布器对同一指纹和目标应给出一致结论；尚未验证的消费者单列。
7. **收口并反馈。** 分别报告修改、自动验证、连接、实际执行/发布和真人验收。获准修改时按来源收录和更新动态规范记录脱敏回执；只读只输出待收录摘要。通用缺口走 `#Seed反馈`，项目专属事实留在本项目，不把本次目标变成 Seed 默认。

## 工作台适配契约

- 工作台展示共享声明、本机绑定、消费者支持、检查时间和证据有效性；凭据只展示可用性及必要的安全摘要，不展示值或可兑换句柄。
- “环境配置”维护声明与引用；“项目诊断”关联断点和修复任务；“Seed 规范”显示版本、支持范围与升级预览。三者引用同一来源和指纹，不复制配置或另存一份完成状态。
- 通过现有任务预览/确认和 ChangeSet 流程提交修复；允许范围来自项目和 Host 白名单，项目声明不能扩张 Host 权限。界面/页面请求保持有界只读，不自动连接生产或执行修复。
- 任务结果关联原问题、范围和修复后指纹；重新读取 Seed/消费者证据后再解除对应问题。不能仅凭任务完成或文件存在将全部健康标绿。
- 未采用的可选运行健康、缺少的可选集成显示 `not_adopted`/不适用；已有原生能力优先适配，不能为修复而强制安装另一套组件。

## 验证矩阵

| 场景 | 预期 |
| --- | --- |
| 工作台已配置，旧脚本只读旧文件 | 定位 consumer_adapter_gap；适配消费者并从原入口回读，不索要明文或重复录入 |
| 两来源指向不同环境/主机 | 明确冲突并保留原值；未裁决前停止依赖该目标的动作 |
| 工具或运行进程版本落后 | 区分源码已实现、安装未更新、进程未重载；输出版本证据及受控更新计划 |
| 引用失效、权限不足、主机身份变化 | 分类并失败关闭；不猜测绑定、放宽主机校验或尝试其他凭据 |
| 只读调用、可选组件未采用 | 零写入；未采用不转成故障、不自动启用 |
| 已授权修复后重复检查 | 原入口消费正确来源；历史资源保留；无新增差异；回执不越级宣称发布成功 |

## 禁区与覆盖规则

禁止输出原始凭据、私钥、连接串、原始存储快照或未脱敏日志；不得在命令参数、共享文件或诊断报告中物化秘密。不得为通过检查修改目标身份、清空历史、禁用安全门或随意回退。用户最新明确要求和项目权限/发布规则优先；与其他指令交集时，诊断在此定位，安装、发布、模板升级各走专门入口，不因本指令自动触发。
