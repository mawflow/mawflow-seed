# ChatGPT 到 AI 的通用交接

当 ChatGPT 或其它规划型助手需要把任务交给可执行 AI 时，使用普通 Markdown，至少包含：目标、范围、禁止项、验收标准、已知证据和期望交付物。

接收方 AI 必须先读取本项目 `AI_START_HERE.md`，遵守项目边界，并区分“已修改”“已验证”“已上线”和“已由真人验收”。不得把聊天中的账号、密钥或本机绝对路径写入仓库。

建议格式：

```markdown
# 任务：<一句话目标>

## 范围
- 允许修改：...
- 禁止修改：...

## 验收
- ...

## 已知证据
- ...
```

从 GitHub 等远程仓库接力时，附 owner/repository、branch/ref、commit SHA（不可得时标为未知）、已读路径与内容缺口；接收方先核对版本再实施。只读网页会话没有实际执行的测试、Git 写入和部署均标为未验证。

## 文件接续中的来源验证

接续检查应能在新会话复现。`check-event` 需要原始事件 JSON；来源页的 `content_contract` 是归一化来源契约，不能直接充当原事件输入。若后续需要复用 `check-event`，在允许路径保存最小可复用输入或明确重建步骤，不保存整段聊天。原事件已不可得时如实说明，不编造检查结果。

持续更新的检查点与验证记录避免互相记录哈希：证据引用固定版本文件或快照；可变恢复点用普通引用并在新 run 核对差异。来源冲突/哈希变化需要保留原结果并追加新事件，不能删旧来源页再用同一 ID 重录来绕过幂等保护。不要从来源事件哈希一致推断 Git 提交、所有文件或资源状态未变化，应分别核对。

共享交接命令使用可移植项目相对路径与逻辑解释器名称；机器专用解释器、端口和路径留在忽略的本机配置。某个解释器缺依赖只证明该解释器不可用；可只读检查已有环境，但不自动安装、改全局配置或宣称项目不能开发。

如果尚无 update_note 且动态生成页从未创建，`generate-update-notes.py check` 的缺页结果只说明视图未生成，不证明 Agent 入口损坏。纯内部流水按更新规范判断 not_needed；不要为消除非适用检查的报错越权生成或改写页面。需要更新动态时仍执行完整 record/render/check，不把未生成当已通过。

WorkBuddy文件对话适配验收前，由控制侧核对并准备MAW运行环境；环境缺失或版本过旧时，先按已有授权升级官方稳定环境，再回读健康和真实检查。WorkBuddy任务只复用准备好的运行环境完成文件任务，环境安装/对齐单独处理与记录，不计作其对话适配任务完成度。
